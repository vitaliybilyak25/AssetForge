# Adobe Stock CSV Output Package Specification

**Document type:** Channel Adapter Specification
**Profile:** `stock/adobe-stock`
**Layer scope:** Channel Adaptation Layer (Layer 3) output format
**Status:** MVP2 — first business case specification
**Cross-references:** story #24 (this document), story #23 (Adobe Stock category taxonomy), story #26 (validation rule implementation), story #85 (release rules)

---

## Overview

This document specifies the Adobe Stock bulk upload CSV format produced by the Channel Adaptation Layer (Layer 3) for the `stock/adobe-stock` Content Profile. It defines each column's exact name, data type, required or optional status, character and count limits, the CAR field or Content Profile dimension that is the authoritative source, the generation rule, and conformant and non-conformant example values.

The Channel Adaptation Layer receives Generated Content from the Content Generation Layer (Layer 2) — plain-text Title, keyword list, Category code, and Releases value — and formats it as a CSV row with a header matching the column set below. The Channel Adaptation Layer does not author content; it formats, validates, and serialises what Layer 2 has produced.

The Adobe Stock CSV format contains exactly five columns. No additional columns exist. No columns defined here may be omitted from the header row.

## Column Specifications

### 1. Filename

**Column name:** `Filename`

**Data type:** String

**Required / Optional:** Required

**Limits:**
- Must be non-empty.
- Must be a valid file name including extension (e.g., `.jpg`, `.png`, `.mov`).
- No path separators or directory components — file name only.
- No character limit is imposed by AssetForge beyond those constraints; the value is passed through as received from the asset ingest record.

**Source mapping:**

The `Filename` column is sourced from the **asset ingest record**, not from the Canonical Asset Record (CAR). The CAR records observations about the asset's visual content; it does not record the asset's file system identity. The ingest record carries the original file name assigned at upload time. The Channel Adaptation Layer reads the ingest record for this value; it does not derive it from any CAR field.

**Generation rule:**

The Channel Adaptation Layer copies the file name — including extension — verbatim from the asset ingest record. No normalisation, transformation, or truncation is applied. The value must match the file name used when the corresponding asset file is uploaded to the Adobe Stock contributor portal, as Adobe Stock uses the Filename column to associate the CSV row with the uploaded file.

**Conformant example:**

```
woman-home-office-standing-desk-2025-09.jpg
```

**Non-conformant example:**

```
/uploads/2025/09/woman-home-office-standing-desk-2025-09.jpg
```

Violation: the value includes a directory path prefix. The `Filename` column must contain a file name only, not a file path. Rule ID `filename-no-path` (implementation scope: story #26).

### 2. Title

**Column name:** `Title`

**Data type:** String

**Required / Optional:** Required

**Limits:**
- Minimum: 1 character (must be non-empty).
- Maximum: 200 characters.
- Case convention: sentence case — the first word is capitalised; subsequent words are lowercase unless they are proper nouns.
- Brand names must not appear in the Title. If the CAR's `text.logo_marks_detected` array is non-empty or `risk.trademark_flag` is `true`, the Content Generation Layer must suppress brand name terms from the generated Title in accordance with the `stock/adobe-stock` Content Profile's Forbidden Content dimension (`forbidden_content.content_types`: competitor brand names, visible brand marks).

**Source mapping:**

The Title is generated by the Content Generation Layer (Layer 2) from:
- `objects.primary_subject` — the single dominant subject identified in the CAR; used to anchor the title phrase.
- `objects.detected_subjects` — secondary objects and scene elements that contextualise the primary subject.
- `activities.primary_activity` — the dominant activity or action; incorporated when the scene is active.
- `location.setting_descriptor` — the specific setting type; used to complete the scene description.
- `location.environment_type` — broad indoor/outdoor classification; provides environmental context.

Content Profile dimensions governing generation:
- `tone.register`: `factual`
- `length_limits`: `unit: characters`, `min: 1`, `max: 200`
- `language.primary`: `en-US`
- `forbidden_content.terms` and `forbidden_content.content_types`: brand names suppressed.

**Generation rule:**

The Content Generation Layer constructs a factual, scene-describing sentence or noun phrase that names the primary subject and its context. It applies sentence case, stays within 200 characters, omits brand names identified in `text.logo_marks_detected`, and writes in English (US). The Channel Adaptation Layer validates the final Title against the `title-required` and `title-max-length` validation rules before including the row in the Output Package.

**Conformant example:**

```
Woman working at standing desk in bright home office
```

Sentence case; 52 characters; no brand names; factual description; English (US).

**Non-conformant example:**

```
WOMAN WORKING AT A STANDING DESK IN A BRIGHT HOME OFFICE WITH HER MACBOOK PRO LAPTOP OPEN ON THE DESK WHILE SHE TYPES AND LOOKS AT THE SCREEN IN A SUNLIT ROOM WITH LARGE WINDOWS AND SHELVES BEHIND HER AND NATURAL LIGHT COMING THROUGH THE GLASS
```

Violations:
- All-caps — violates sentence case convention. Rule ID `title-sentence-case` (implementation scope: story #26).
- 244 characters — exceeds the 200-character maximum. Rule ID `title-max-length` (implementation scope: story #26).
- Brand name "MacBook Pro" present — violates the Forbidden Content constraint. Rule ID `title-no-brand-names` (implementation scope: story #26).

### 3. Keywords

**Column name:** `Keywords`

**Data type:** String — a single comma-separated list of keyword terms or short phrases.

**Required / Optional:** Required

**Limits:**
- Minimum: 5 keywords.
- Maximum: 49 keywords.
- Format: comma-separated; no surrounding whitespace between the comma and the next keyword term.
- Language: English (US).
- Ordering: most important keywords first (relevance descending), as specified in `keyword_rules.ordering: relevance_descending`.
- Capitalisation: lowercase, as specified in `keyword_rules.capitalisation: lowercase`.
- Formats allowed: single words and short phrases (`keyword_rules.formats_allowed: [single_word, phrase]`).
- Brand names must not appear in the keyword list (Forbidden Content dimension).

**Source mapping:**

The keyword list is generated by the Content Generation Layer (Layer 2) from all populated CAR categories. Primary source fields, by CAR category:

- **Objects and Subjects:** `objects.detected_subjects` (individual objects as single-word or short-phrase keywords), `objects.primary_subject` (anchor keyword — listed first), `objects.scene_type` (compositional context keywords), `objects.colour_palette` (colour keywords where commercially relevant).
- **People:** `persons.present` (triggers lifestyle/people keywords), `persons.count` (group composition keywords), `persons.age_range_signals` (demographic keywords), `persons.group_composition`, `persons.activity_posture`.
- **Locations:** `location.environment_type` (indoor/outdoor keywords), `location.setting_descriptor` (setting-specific keywords), `location.visual_landmark` (landmark name as keyword, if present), `location.urban_rural_signal`.
- **Text and Logos:** `text.logo_marks_detected` — brand names detected here are excluded from keywords per the Forbidden Content dimension.
- **Activities:** `activities.detected_activities` (activity and action keywords), `activities.primary_activity`, `activities.social_context`.
- **Risk Flags:** no keywords are sourced from Risk Flags; this category drives routing decisions only.

Content Profile dimensions governing generation:
- `keyword_rules.min_count`: 5
- `keyword_rules.max_count`: 49
- `keyword_rules.formats_allowed`: `single_word`, `phrase`
- `keyword_rules.capitalisation`: `lowercase`
- `keyword_rules.separator`: `comma`
- `keyword_rules.ordering`: `relevance_descending`
- `language.primary`: `en-US`
- `forbidden_content.terms` and `forbidden_content.content_types`: brand names suppressed.

**Generation rule:**

The Content Generation Layer assembles a ranked keyword list, most important keyword first, drawn from all seven CAR categories. It applies lowercase normalisation, comma-separation with no surrounding whitespace, enforces the 5–49 count range, and excludes any term matching the Forbidden Content dimension. The Channel Adaptation Layer validates the final keyword list against the `min-keyword-count` and `max-keyword-count` validation rules before including the row in the Output Package.

**Conformant example:**

```
woman,standing desk,home office,remote work,productivity,working from home,technology,laptop,modern workplace,professional,indoor,natural light,lifestyle,business,focus,female,adult,entrepreneur,desk,workspace,bright,contemporary,interior,daylight,computer,typing,seated,window,shelf,plant,minimalist,clean,organized,white,background,copy space,horizontal,color,photography,stock
```

41 keywords; all lowercase; comma-separated; relevance-descending order; no brand names; English (US); within the 5–49 range.

**Non-conformant example:**

```
woman, standing desk, home office, MacBook Pro, remote work
```

Violations:
- 5 keywords — meets the minimum but the example illustrates a brand-name violation.
- "MacBook Pro" — brand name in keyword list violates the Forbidden Content constraint. Rule ID `keywords-no-brand-names` (implementation scope: story #26).
- Space after each comma — violates the `keyword_rules.separator: comma` convention (no surrounding whitespace). Rule ID `keywords-separator-format` (implementation scope: story #26).

### 4. Category

**Column name:** `Category`

**Data type:** Integer — Adobe Stock numeric category code.

**Required / Optional:** Required

**Limits:**
- Must be a valid Adobe Stock numeric category code from the platform's defined category taxonomy.
- Must not be empty, zero, or a non-numeric value.
- The full list of valid numeric codes and their corresponding category names is specified in the Adobe Stock Category Taxonomy (Acceptance Criteria reference: story #23; note that story #23 had not been accepted at the time this specification was authored — implementers must cross-reference story #23 for the authoritative code list once accepted).

**Source mapping:**

The Category code is resolved by the Content Generation Layer (Layer 2) using:
- `objects.scene_type` — the broad compositional classification drives primary category selection.
- `objects.primary_subject` — the dominant subject is cross-referenced against the Adobe Stock category taxonomy to identify the most specific matching category.
- `activities.primary_activity` — when present, the dominant activity may refine the category selection (e.g., distinguishing a sport category from a lifestyle category).
- `location.setting_descriptor` — the setting descriptor can distinguish categories that share subject matter but differ by context (e.g., business vs. home office vs. travel).

Content Profile dimension governing resolution:
- The `stock/adobe-stock` Content Profile specifies the Adobe Stock category taxonomy as the target taxonomy. The Category field is listed as Required in the `fields` dimension.

**Generation rule:**

The Content Generation Layer maps the CAR's primary subject and scene type to the closest matching Adobe Stock numeric category code using the taxonomy defined in story #23. When multiple categories could plausibly apply, the most specific category that matches the primary subject takes precedence. The resolved integer code is passed to the Channel Adaptation Layer as part of the Generated Content Handoff. The Channel Adaptation Layer writes the integer value directly to the Category column without transformation.

**Conformant example:**

```
3
```

A valid Adobe Stock numeric category code (e.g., representing the Business category, as illustrated in `Reqs/Sample_Adobe_Stock_CSV_upload.csv`).

**Non-conformant example:**

```
Business
```

Violation: the column must contain the numeric category code, not the category name as a string. Rule ID `category-must-be-numeric` (implementation scope: story #26).

### 5. Releases

**Column name:** `Releases`

**Data type:** String — either an empty string or a comma-separated list of release document file names.

**Required / Optional:** Required (column must be present; value may be empty depending on release state — see three-state behaviour below).

**Limits:**
- When populated: one or more release document file names, comma-separated with no surrounding whitespace between the comma and the next file name.
- Each file name must exactly match the file name used when uploading the release document to the Adobe Stock contributor portal.
- When empty: an empty string (`""`).
- No character limit is specified for the column value itself; release file name length is governed by the contributor portal's file naming constraints, which are outside AssetForge's scope.

**Source mapping:**

The Releases column value is governed by three CAR Risk Flag fields and by human-reviewer confirmation input:
- `risk.model_release_required` (boolean, Conditional) — triggers State B when `true` and no confirmed release is on file.
- `risk.property_release_required` (boolean, Conditional) — triggers State B when `true` and no confirmed release is on file.
- Human-reviewer-confirmed release file name(s) — provided during the Approval Requirements review step; this is not a CAR field. The confirmation mechanism is deferred to a separate design story (see `docs/adobe-stock-release-rules.md`, story #85).

**Three-state behaviour** (specified in full in `docs/adobe-stock-release-rules.md`, Section 3):

| State | Condition | `Releases` column value | Export behaviour |
|---|---|---|---|
| **A — Release confirmed present** | `risk.model_release_required = true` or `risk.property_release_required = true`, and a human reviewer has confirmed valid signed release document(s) are on file | The exact file name(s) of the uploaded release document(s), comma-separated | Output Package may proceed to delivery |
| **B — Release required, absent or unconfirmed** | `risk.model_release_required = true` or `risk.property_release_required = true`, and no confirmed release record is available | `""` (empty string) | Output Package must not be delivered; asset is held in the Approval Requirements review queue |
| **C — Release not required** | `risk.model_release_required` is absent or `false`, and `risk.property_release_required` is absent or `false` | `""` (empty string) | Output Package may proceed to delivery without release-related gating |

Both State B and State C produce an empty `Releases` column value. They are distinguished by the presence or absence of active risk flags on the CAR — not by the CSV column value alone. Downstream systems and human reviewers must read the CAR risk flag values to determine which state applies.

**Editorial exemption:** When `risk.editorial_only = true` on the CAR, the editorial path applies. Release requirements do not block Output Package generation for the editorial submission. The `Releases` column is left empty (State C semantics) for the editorial Output Package. If a human reviewer subsequently overrides `risk.editorial_only` and a commercial Output Package is generated, full release rules apply to that commercial Output Package. See `docs/adobe-stock-release-rules.md`, Section 5.

**Generation rule:**

The Channel Adaptation Layer writes the Releases column value based on the release state determined during the Approval Requirements review step. For State A, it writes the reviewer-confirmed release file names verbatim in comma-separated format. For States B and C, it writes an empty string. The Channel Adaptation Layer does not evaluate release trigger conditions — those are evaluated by the Asset Intelligence Layer (risk flags) and the Content Generation Layer (routing to review). The Channel Adaptation Layer writes what the review step has recorded.

**Conformant example — State A (release confirmed):**

```
model-release-jane-doe-2025-03.pdf,property-release-brooklyn-loft-2025-03.pdf
```

Two confirmed release files; comma-separated with no surrounding whitespace; file names match the names used when uploading to the Adobe Stock contributor portal.

**Conformant example — State C (no release required):**

```

```

Empty string — no release flags are active on the CAR; no release documentation is required.

**Non-conformant example:**

```
model release - Jane Doe (March 2025).pdf
```

Violations:
- File name contains spaces and parentheses — the release file name must exactly match the file name as uploaded to the Adobe Stock contributor portal. If the uploaded file was named with spaces, this would be conformant; however, the example illustrates a common error where the reviewer provides a descriptive label rather than the exact file name. Rule ID `releases-exact-filename-match` (implementation scope: story #26).

The following table consolidates all column constraints for the `stock/adobe-stock` CSV Output Package. All validation rule IDs prefixed `as-` are in scope for implementation in story #26.

| Column | Required / Optional | Data Type | Minimum | Maximum | Additional Constraints | Validation Rule IDs (story #26 scope) |

| `Releases` | Required (column present; value may be empty) | String | 0 characters (empty string permitted) | No platform limit | Three-state behaviour per `docs/adobe-stock-release-rules.md` Section 3; when non-empty, file names must exactly match contributor portal upload names; no surrounding whitespace around comma separators | `releases-state-enforced`, `releases-exact-filename-match`, `releases-separator-format` |

## Template Verification

Verified against `Reqs/Sample_Adobe_Stock_CSV_upload.csv`, accessed 2026-09-28. Column set: Filename, Title, Keywords, Category, Releases.

The sample CSV contains a header row with exactly five columns — `Filename`, `Title`, `Keywords`, `Category`, `Releases` — in that order. Two data rows are present: one for a `.jpg` asset and one for a `.mov` asset. Both rows populate all five columns; the `Releases` column in the sample contains contributor names rather than release document file names (the sample uses display names as illustrative placeholder values). The column set and column names confirmed here are the authoritative reference for the Channel Adaptation Layer's CSV serialisation. No additional columns exist in the Adobe Stock bulk upload CSV format.
